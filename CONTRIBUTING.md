# Contributing

Thanks for helping. Every Aūno tool is meant to be simple enough to read in one sitting, so small, clear changes are the best kind.

## Ways To Help

- **Report a bug.** Open an issue using the bug form. Include steps to repeat it and which browser you used.
- **Share an idea.** Start a discussion first, so we can agree on the shape before anyone writes code.
- **Add a sample.** New fictional sample documents help people see what a tool can do.
- **Improve the words.** Clearer instructions are as valuable as new features.

## How A Change Lands

1. Fork the repository and create a branch for your change.
2. Make the change. Read the repository's `AGENTS.md` first: it lists the design and writing rules, and coding agents follow it too.
3. Open the page in a browser and check it on a wide screen and a phone width.
4. Open a pull request using the template. Checks run automatically; a first-time contributor's checks start after a maintainer approves them.
5. A maintainer reviews it. Changes are squashed into one commit when merged.

## Ground Rules

- **Sample content stays fictional.** Never include real company names, real documents, or anything private.
- **No new dependencies without a reason.** Tools work as plain files with nothing to install wherever possible.
- **Plain language.** Short words, no acronyms, Title Case headings.
- **Be kind.** See the [Code of Conduct](CODE_OF_CONDUCT.md).

By contributing, you agree your work is shared under the repository's MIT license.
